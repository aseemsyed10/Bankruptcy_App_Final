# Bankruptcy Risk Explorer

Full-stack educational bankruptcy classifier using logistic regression, feature selection, SHAP explainability, Great Expectations data validation, a FastAPI inference service, and a Streamlit dashboard.

## Run

With Docker: `docker compose up --build` then visit http://localhost:8501 (UI), http://localhost:8000/docs (API).

Without Docker (Python 3.11): install `requirements.txt`; run `python train.py`, `python explain.py`, and `uvicorn main:app --reload`. In a second terminal install `frontend/requirements.txt`, then `streamlit run frontend/app.py`.

Training reads `data.csv` with `Bankrupt?` as target. The initial holdout is stratified; training-only cross-validation chooses the number of selected features and logistic regression regularization strength. `artifacts/model.joblib` bundles the imputer, scaler, selected features, and classifier with the original feature order. `artifacts/metrics.json` contains holdout and CV scores. `artifacts/shap_beeswarm.png` is generated by `python explain.py`.

Validation: `validation.py` uses Great Expectations 0.18 to check row counts, required target, valid binary labels and predictor types. Failed validation aborts training. Run `pytest -q` for smoke tests.

The frontend accepts a named-feature CSV or a single manually entered company and displays class, probability and local log-odds SHAP contributions. Default zero inputs are placeholders, **not realistic company financial values**. Probability estimates are uncalibrated and must not be used as financial advice.

### API

`GET /features` returns required financial names; `POST /predict` expects `{"values": {"feature name": 0.1, "other feature": 0.2}}` with *every exact feature name* and returns prediction, probability and (where available) SHAP contributions. API errors on missing or extra predictors.

### Changes from initial submission

The original submission had an empty Streamlit frontend, no fitted feature selector, no calculated SHAP attribution and no implemented Great Expectations validation. This branch addresses these items and separates training from inference. Do not present this as the original graded submission; check tests and deployment before merging.

## Model refinement (October 2026)

The revised pipeline uses a fixed 20% stratified holdout, and divides the remaining development data into **disjoint** model-fitting (60% total), sigmoid-calibration (10%), and threshold-tuning (10%) partitions. Five-fold cross-validation on the fitting partition selects up to 10/20/40/95 features and the regularization parameter, optimizing average precision. A fixed-regularization all-95-feature CV baseline is reported for comparison.

A Platt logistic calibrator fits the model's decision scores on calibration data only. The review-alert threshold is chosen on the separate threshold-tuning partition by maximizing precision while requiring at least 70% bankruptcy recall there (if feasible). The final holdout remains untouched until evaluation. It reports holdout PR-AUC, ROC-AUC, Brier score (raw vs calibrated), confusion matrix, precision, recall and F1.

The *risk estimate* displayed in Streamlit is now the sigmoid-calibrated score, not the original class-weighted logistic probability. The binary output is explicitly a **screening flag**, not a factual determination of bankruptcy. SHAP values still describe the underlying linear model log-odds **before calibration**, not shifts in calibrated probabilities. Review `artifacts/metrics.json` before interpreting results.

**Limitations:** Only approximately 10% of data is allocated to each calibration and threshold set, and the minority class is rare. Threshold precision and calibration may therefore be unstable. Comparisons use the same source dataset, not out-of-time or external company samples. Better portfolio validation would use temporal or external testing, confidence intervals and calibration curves. Do not treat any prediction as financial advice.

After pulling this branch, rebuild images to get the refined training artifacts: `docker compose up --build`. Old containers continue to serve old artifacts until rebuilt.

## Two screening modes and audit plots
The dashboard and API now support `high_recall` and `higher_precision`. Both thresholds are chosen **only** from the threshold-development partition: the former requires at least 85% recall there (where feasible), the latter at least 70%. These constraints are not guarantees on the final holdout or new companies. `artifacts/metrics.json` reports the independent holdout confusion matrices, precision, recall, and F1 for both modes. `artifacts/precision_recall_curve.png` and `artifacts/calibration_curve.png` are exported automatically by training as diagnostics.

Run `docker compose up --build` after `git pull` to rebuild the model and frontend, and test both modes using the same uploaded company row. Neither threshold is appropriate for regulated financial decisions without external validation.
